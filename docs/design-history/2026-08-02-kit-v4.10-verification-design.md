# Kit v4.10 設計：驗證閉環——驗證器可信度、驗證終點、不可逆前置閘

> 2026-08-02，user 發起（本輪對話方向一「真機驗證/觀察層」的落地版）。
> RED 收據 = 全機隊 LESSONS 掃描（13 專案 85 條，聚 11 類；原始報告見
> 本次 session，聚類計數可回溯至各專案 LESSONS 條目）。本檔是設計權威。

## 1. 收據基礎（按強度排序）

- **聚類 1（10/13 專案）驗證管道自身說謊**：quant `pytest | tail && commit`
  pipe 吞 exit code 同 session 三犯；kaf「綠燈 CI 掩護 12 天翻譯全滅」；
  eureka「『零命中』與『沒在跑』輸出上長得一模一樣」；agent-rpg「全黑畫面
  也能綠」。kit-judgment #3 要求「跑過」，但從未要求**驗證器本身先被證明
  會紅**。
- **聚類 8+2（合計 ~8 專案）驗證終點錯位 + 靜默降級**：anatomy「localhost
  綠、對外 502」；portfolio user 逐字「你每次都叫我自己在瀏覽器看，但是
  每次你都沒開服務」；case-pick「每日上限靜默失效」；sekai `174 !== '174'`
  讓 DELETE 守門靜默失效。kit 對「怎麼驗」有規則、對「**在哪個終點驗**」
  空白。
- **聚類 4（6 專案）不可逆操作缺前置保護**：anatomy `;` 讓 downgrade 照跑
  「永久抹掉 304 列」；kaf「上游是滾動視窗時，DB 是唯一的歷史副本」。
  cholate-blog R1-R5 已演化出通用設計（preflight／fail-closed 哨兵／正向
  證明才刪／回補量測）。
- **Meta 收據（聚類 7，5 專案）**：kit-judgment #5/#6 已覆蓋的行為照樣
  高頻違反；anatomy 逐字「本條已寫在 LESSONS 裡仍再犯一次」——prose 極限
  的直接證據，預算優先投機械檢核（與 v4.9 減法哲學同向、與
  harness-diagnosis §三.7 推論一致）。

## 2. Workstream 1：驗證器可信度（hook + S6）

**hook 層（機械，擴充 tool-breaker.sh 的 PreToolUse Bash 路徑）**：
「verifier-pipe guard」。**契約（codex 計畫審 R1 修正版——原三段獨立
grep 語法盲，被實測打穿）**：
1. 前置豁免（寧漏勿誤擋的實現）：命令含 heredoc `<<`、或以
   echo/printf 起頭（寫文字非跑測試）、或字串含 `pipefail`（含註解與
   `set +o` 變體——文件化的 false-negative 方向）→ 不攔。
2. 正規化：換行以 `;` 摺疊（newline 即分隔符——`pytest|tail␊git commit`
   與 `&&␊git commit` 都進得了序列比對）。
3. **單一有序 regex**：左錨定的測試執行器（前一字元限 行首/`;`/`&`/
   `(`/空白——引號前綴不成立，殺掉 `printf '%s' 'pytest | tail'` 類
   誤擋）→ 單管道（`[^|]\|[^|]`，排除 `||`）→ 其後 `(&&|;)` 鏈到
   `git commit|push`。順序內建：commit 在管道**之前**不攔。
4. 明文不防（unguarded，寫進 hook 註解與 S6）：跨 Bash 調用拆分
   （測試一條、commit 下一條——stateful 防護超出範圍，交 S6 prose 與
   review 層）；引號內含完整形狀且同串又真 commit 的極端構造。
**插入點與 telemetry（釘死，不留 align-later）**：插在 canonical
hash/state 更新與 call 事件記錄**之後**、通用 N≥3 熔斷 deny **之前**
——被攔的調用仍參與 spiral 鏈（invariant 不破），且 pipe-guard 訊息
優先於通用熔斷訊息；telemetry 沿用既有 schema（`e:"deny"` 加
`k:"pipe-guard"`），呼叫既有 log_event 的實際簽名。逃生口沿用
`KIT_BREAKER=off`。
RED = quant 三犯原始形狀重放；GREEN = hooks-smoke 測項矩陣含誤擋
反例（引號/heredoc/順序反轉）、漏網方向鎖定（set +o pipefail）、
spiral 交互與 toollog schema。

**S6 prose 層（verification-signals 新節「驗證器可信度」）**：
1. **紅樣本自檢**：新建或修改任何驗證器（測試、斷言、CI 步驟、守門
   條件）後，先餵一個已知壞樣本證明它會紅，才准信它的綠。
2. **零與死要可分**：「零命中/零處理」與「根本沒在跑」的輸出必須
   可區分——計數輸出（processed N / matched M），N=0 是結果、無輸出
   是故障。
3. **fail-loud 降級**：每個 fallback/catch 必須產生 user 可見的警示或
   計數；「功能正常但一直降級」= 聚類 2 的 6 專案坑。
4. 既有「否定斷言腐化」教訓（聚類 9）併此節：否定斷言只准比對唯一
   可能的違規寫法，否則寫正面斷言。

## 3. Workstream 2：驗證終點 + 觀察層（S7）

**verification-signals 新節「驗證終點與觀察層」**：
1. **終點 = user 可見面**：宣告完成前的驗證必須發生在交付終點——
   web 專案 = prod/preview build 的**對外 URL** 實測（非 dev server、
   非 localhost healthz）；CLI/服務 = 由 AI **自己把服務起起來**再驗
   （portfolio 收據：叫 user 看瀏覽器但服務沒開）。「dev 綠」一律
   標 changed-but-not-verified-at-endpoint。**授權邊界（codex R1）**：
   本條只授權「用既有的、已授權的 endpoint 驗」——建立或改動部署仍
   受 R3.4 管；無既有授權 endpoint 時，正確動作是回報
   endpoint-unverified，**不是自行部署**。
2. **觀察層閉環**：debug 資訊不夠 → 自己補結構化 log（含關鍵狀態與
   計數）→ 重跑 → 讀 log → 再定位——不等 user 貼訊息。log 的加/收/
   搜是 AI 的工作，起服務也是。
3. **測試階梯**：純邏輯 function → jsdom（React/Next 純 UI 邏輯）→
   真瀏覽器。升級條件（codex R1 修正）：**正確性依賴瀏覽器 runtime
   即升級**——hydration、routing、瀏覽器 API、事件/互動流程、端到端
   user flow，不只渲染差異。同 runtime 內優先打真實鏈路而非 mock——
   mock 是在假設一個 contract，contract 有洞（S5 的延伸）。
4. 與 S1 分工：S1 管「好不好看」（截圖迴圈），本節管「活不活著、
   通不通」。

## 4. Workstream 3：不可逆操作前置閘（S8）

**verification-signals 新節「不可逆操作」**（cholate-blog R1-R5 通用化；
快照條經 codex R1 強化——「非空」不是可回復的證據）：
1. **preflight 快照（可回復才算數）**：動任何不可逆目標（DB 刪改、
   migration downgrade、覆蓋檔案、force push）前，先產出可回復實體，
   且四項齊備才算快照成立：(a) 快照指令 exit 0；(b) 目標身分對得上
   （dump 的是要動的那張表/庫，不是同名別庫）；(c) 內容驗證——
   列數/檔數/checksum 對照來源（**合法的空狀態要明列為預期值**，
   零列可以是對的）；(d) **回復演練**——DB/migration 類技術上可演練
   就必須在隔離環境端到端 restore 一次（dump 能 parse ≠ 能 restore：
   roles/extensions/權限/版本差都在 restore 才炸，codex R2-P2）；
   確實無法演練的媒介走明文例外：獨立驗證過的回復機制 + 變異前
   取得 user 認可，**parse-only 永不冒充演練**。
2. **fail-closed 哨兵**：守門條件必須型別安全且反向預設（比對失敗 =
   擋下，不是放行——sekai `174 !== '174'` 收據）。
3. **正向證明才刪**：刪除的依據必須是「證明了它該刪」，不是「沒證明
   它不該刪」。
4. **回復決策先於變異**：動手前先寫下「量測超差時怎麼回復」（用哪個
   快照、哪條指令、判準是什麼）——事後才想回復程序 = 損失已發生
   （codex R1：事後停手回報時傷害已不可逆）。操作後立刻量測結果集
   對照預期，超差即依預寫程序回復並回報。
5. 與 R3.4 分工：R3.4 管「要不要先問 user」；本節管「獲准之後怎麼做
   才不會變成永久損失」。
**hook 不做**（明文）：`DELETE|DROP|rm -rf` 的命令字串判別誤擋率過高
（scratch 清理、測試 fixture 皆合法），與 harness-diagnosis「Bash 命令
解析保護不做」同理由。strip condition：機隊再出現一次繞過 S8 的資料
損失事故 → 重評 ask-mode hook。

## 5. 維護件

- **LESSONS 精簡門檻修正**（kit-evolution）：「300 行或 8KB」→
  「300 行；byte 門檻僅適用 ASCII 為主的檔案（中文字 3 bytes，以行數
  為準）」。收據：anatomy 19.6KB 但僅 221 行，檔頭自申門檻對中文偏嚴。
- **judgment-matrix R5 加一列**（聚類 3，6 專案）：藉口「用最新一筆/
  標題/時間戳就能判斷」→ 現實「查狀態用狀態欄位、識別用唯一 id——
  插入時間 ≠ 邏輯狀態、標題 ≠ 身分」。
- **機隊 follow-up（非 kit repo 工作）**：anatomy-rag（2.4×）、case-pick、
  eureka 三檔 LESSONS 待各自 session 精簡；鋪 v4.9+v4.10 時提醒。

## 6. 明確不做（防 scope creep）

- `[env]` preflight／proj doctor：機隊收據未進前三（聚類 6 的痛是 cwd/
  docker 不是缺 runtime），掛回候選清單，等原始痛（「電腦不符」）在
  機隊實際出現。
- wiki/代碼綁定：維持 R1.2 二犯觸發，不動。
- 破壞性命令 hook、cwd 漂移 hook：誤擋率考量，見 §4/等收據。
- 打分制：不引入（機隊資料再次支持 true/false——「可分辨的紅」比
  分數有效）。
