# Kit v5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 multi-agent-starter 從「複製進每個專案」的 v4 變成「機器裝一次」的 v5：Claude Code plugin + 本機 git guard + 機隊 audit + 無損遷移，kit repo HEAD 對陌生人乾淨。

**Architecture:** 產品搬到 `plugin/`（hooks/rules/skills/agents/guard/templates），每支 hook 以專案根的 `kit.toml` 自我閘控；常駐 rules 由 SessionStart hook 分兩段注入；`bin/kit`（Python 3.11+ 純標準庫，`cli/` 套件）負責 setup/doctor/init/migrate/audit/guard；全域 `core.hooksPath` 指向 kit 生成的 shim，shim 跑 `plugin/guard/*.sh`（bash+git+grep+gitleaks）再鏈到 repo 本地 hook。

**Tech Stack:** bash 5 + jq + git（hooks、guard）；Python 3.11+ stdlib（`tomllib`, `argparse`, `json`, `urllib`, `hashlib`）；gitleaks 8.30.1；osv-scanner 2.7.0；`gh` CLI；Claude Code ≥ 2.1.277（本機 2.1.303）。

**Spec:** `docs/design-history/2026-10-19-kit-v5-design.md`（含「修訂 2026-10-19」三條）。Brief：`~/.repo-cleanup/kit-v5-brief.md`（本機）。Plan 內以 §n 指設計檔章節、Dn 指設計者決定。路徑慣例：`<kit_root>` = 本 repo 的 checkout（owner 機器上是 `~/multi-agent-starter`）；`$SCRATCH` = 實作 session 的 scratchpad 目錄；`$KIT_TOOLS` = 含 gitleaks/osv-scanner 二進位的目錄——**兩者由 orchestrator 在每次派工 prompt 中給出**，本檔刻意不寫絕對路徑（本檔會被 commit，須遵守下方字面值規則）。

## Global Constraints

- 所有 Claude hooks 與 guard 腳本只用 bash + jq + git + grep/sed/awk（D15）；`cli/` 只用 Python 標準庫，`python3 --version` ≥ 3.11（本機 3.12.3）。
- plugin 名 `kit`、marketplace 名 `multi-agent-kit`、產品目錄 `plugin/`（D1）；skills 叫 `/kit:review` `/kit:skip-review` `/kit:dispatch` `/kit:research-first` `/kit:judgment` `/kit:verify-signals`（D3/D4）。
- rules 預算：五檔總 bytes ≤ **20,480**（棘輪不升）；每個注入段 ≤ **9,500 chars**（§4.3）。
- 權限基線只剩 `Bash(git status*)` `Bash(git diff*)` `Bash(git log*)` `Bash(git show*)` `Bash(ls*)`，**刪 `Bash(timeout *)`**（D19）。
- 任何會被 commit 的檔（含 tests、fixtures、本 plan、design doc）**不得**含私人專案名、本機絕對路徑（`/home/<user>`、`/mnt/c/Users/<name>`）、金額、uid、bucket、email。測試用字面值一律用假值（`/home/testuser/`、`proj-a`、`11111111-2222-...`）。
- `kit.toml` 的 `protected = [...]` 一行一項、不准行內註解（D7）；bash 用 sed 解析，`kit doctor` 用 tomllib 驗證。
- guard 失效模式：config 缺／`kit_root` 不存在 → **exit 1 + `KIT GUARD: not configured`**；缺 gitleaks → pre-commit warn、pre-push block（D11）；block 訊息永不印被攔字面值。
- `/tmp/claude-kit-*` 狀態檔名與格式**不動**（D9）；`tests/hooks-smoke.sh` 既有 ~1,200 行斷言全數保留。
- 版本：`VERSION`、`plugin/.claude-plugin/plugin.json.version`、`.claude-plugin/marketplace.json` 的 plugin version 三者相等（plugin-validate 斷言）。
- 所有 commit 在分支 `kit-v5` 上；commit message 英文 conventional（`feat(plugin): …`），結尾附本 session 的 attribution 行。**不 merge、不 push、不 tag**——那是 owner 動作（附錄 A）。
- 每個 task 結束前跑該 task 列出的驗證指令，且 `bash tests/run-all.sh` 必須綠（Task 1.4 建立它）。

## Review Focus

spec 隱含、但沒有 task 的測試天然覆蓋的五個失敗模式（每條已在所屬 task 補測試）：

1. **`kit.toml` 存在但被人手寫壞**（protected 行內註解、`visibility` 拼錯）→ hooks 必須 fail-open 到「無 protected」且不崩；`kit doctor` 必須報錯。→ Task 2.3、3.2。
2. **guard 在非 kit repo、非 git 目錄、裸 repo、worktree、submodule 內**跑 → 通用層照跑、不崩、不假陽性；worktree 鏈 hook 用 `--git-common-dir`。→ Task 4.4。
3. **privacy.local.toml 含正規表達式特殊字元或極短值**（例 `value = "a"`）→ 字面值比對必須 fixed-string 且最短長度 ≥ 4，否則整個機隊全紅。→ Task 3.3、4.1。
4. **migrate 跑到一半失敗**（apply 中途 Ctrl-C）→ 重跑必須收斂且 `.claude/kit-version` 讓位閘仍保護；備份目錄已存在不覆蓋。→ Task 3.7。
5. **audit 在離線／`gh` 未登入／repo 無 remote** 時 → GitHub 層 finding 標 `UNKNOWN` 不算 HIGH，退出碼不因此變 2。→ Task 3.8b。
