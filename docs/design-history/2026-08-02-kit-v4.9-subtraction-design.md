## 1. 證據基礎（RED 收據）

- **常駐 context 稅頂到預算**：`.claude/rules/` 五檔 20356B / cap 20480B
  （99.4%），預算機制只擋膨脹、不產生瘦身壓力。v4.0→v4.8 prose 只加不減。
- **instruction audit 欠帳**：`docs/instruction-audit.md` 為此而設，audit
  log 至今空白（「尚未跑過」）。
- **Anthropic 官方方法論**（2026-07-24，[The new rules of context
  engineering for Claude 5 generation models](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models)）：
  對 Claude 5 世代砍掉自家 Claude Code 系統提示 80%+，coding evals 無可測
  退化；18 個 subagent 定義 489→37 行，plan-following 反而改善。六轉向中
  與本版直接相關：Rules→Judgment、Examples→Interface design、Upfront
  context→Progressive disclosure（= 本 kit 的 on-demand 層）。
- **[Prompting Claude Opus 5](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5)**：
  官方點名「legacy harness scaffolding」（外加的驗證步驟指令、double-check
  指令）該刪——此代模型自我驗證，疊加指令造成過度驗證。**明文警告不可
  外推到 Sonnet/Haiku 檔位**——受眾分離的官方背書。
- **Stop gate 連攔收據**：user 回報（2026-08-02 本 session）：批次超過
  150 行後每個動碼輪都被攔。代碼路徑證實（verify-final-review.sh：
  small_change_allow 失效後，turn-scoped 只放行無變更輪）。另
  [Claude Code best practices](https://code.claude.com/docs/en/best-practices)
  載明 Stop hook 連續 8 次 block 會被強制放行——現行連攔行為會撞天花板
  變成靜默失效。
- **反向收據（減法的邊界）**：evals.md Recorded runs 中真實 0 分全部來自
  **長 session 的強模型**（場景 9 = Fable 5 本尊 2026-07-07；場景 10/11、
  13-15 = Opus 4.8）；合成 fresh-context eval 三次採納註記均承認模擬不了
  長 session 退化。規則的目標對象是「疲勞後的強模型」，不是弱模型——
  所以刪除的預設形式是降級，不是消滅（§3）。

## 2. 與腐化路徑的區別（威脅模型自覺）

「強模型不需要限制」同時是 harness-diagnosis §五·3「規則稀釋」的頭號
藉口。本版減法與腐化的區別，三件缺一不可：**user 發起**（本檔即收據）、
**逐條證據**（audit finding / GREEN-without / hook 接管，三者之一）、
**audit log 留痕**（含 retested-kept 的否定結果）。模型日後引用本檔作為
「繼續刪」的授權時，同樣三件缺一不可。

## 3. Workstream A：prose 減法（審計驅動三刀 + 棘輪）

不變量：(a) hooks 執法邏輯不因瘦身而動（gate 重設計是 Workstream B 的
行為變更，各有收據，互不搭便車）；(b) judgment-matrix / verification-
signals 為 on-demand 層，允許變胖（降級目的地）；(c) review isolation、
auth/payment、protected-paths 條款不進刪除候選。

- **Phase 0 — 跑第一次 instruction audit**。fresh read-only subagent 用
  instruction-audit.md 現成 prompt（含 superpowers 重疊檢查）。產出留/刪/
  降清單，逐項附防的失敗模式、proof surface、退場條件。指揮官逐 finding
  對照原文抽驗。結果記入 audit log。
- **Phase 1 — 無爭議刀**（機械縮寫，免行為 eval）：
  1. hook 已物理接管的解釋性散文 → 一句指標 +「被攔時怎麼辦」；
  2. 行內收據壓成日期引用（細節在 evals.md / LESSONS）；
  3. 跨層重複指定 canonical 位置，副本改一句指回。
  驗收 = smoke 過 + review 確認「只縮寫、未改義」。
- **Phase 2 — 判斷刀**（逐條 eval-gated 降級）：audit 標為「補償性/失敗
  模式存疑」的條款跑 **GREEN-without**。方法（codex P1 修正版）：不可用
  session 內 subagent——它繼承含候選條款的規則快照，「拿掉」是假的；
  改用 `claude -p`（Haiku 檔、無 .claude 的 scratch 目錄）做**成對 A/B**
  ——同場景各跑「含條款」與「不含條款」的節錄規則，降級判準 = 不含版
  **相對**不退化（不是絕對分數線）。
  過 → 降級到 on-demand 層或 dispatch 模板，常駐層留一行路由；不過 →
  留下，audit log 記 `retested YYYY-MM-DD, kept`。**真刪僅限 hook 已
  接管者**。每條降級附**回升觸發**：真實 session 再犯（LESSONS 條目
  成立）即升回常駐層——這是對「合成 eval 高估可刪量」的對沖。
- **受眾分離**：指揮官層（rules/）依 Opus 5 指南卸掉 scaffolding 類條款；
  dispatch 模板（kit-dispatch，弱執行員唯一保證送達的載體）**保留**判斷句
  與措辭紀律——官方明文此類指令對 Sonnet/Haiku 檔位仍必要。
- **棘輪**：完工後 smoke 的 rules/ cap 由 20480B 下修至新實際值 +5%。
  沒有棘輪，膨脹會在三個版本內靜默回來。
- **配套規則加法（本版唯一）**：kit-evolution 增「減法紀律」小節——
  降級不消滅 / GREEN-without / 棘輪 / 回升觸發。RED 收據 = 本檔 §1。

## 4. Workstream B：Stop gate 決策點重設計

現況病灶：gate 只有兩個出口（review / user 說 skip），批次破檻後在
review 前**每個動碼輪都 block**（v4.8 turn-scoped 只救無變更輪）。重複
block 零新資訊，且逼近 8-block 強制放行天花板。

新形態：**每次破檻，強制一次明確決策；決策之後閉嘴。**

1. 批次首次跨過 150 行/8 檔 → block 一次，要求三選一：
   - **review**：走 /kit-review，現行語意不變；
   - **defer**：feature 未收斂、此刻 review 無意義。寫一行理由進 defer
     狀態檔；gate 靜默直到批次**再長一個檻距**（每 +150 行一個檢查點）
     才再攔。宣告完成前的 Final review 義務不變（prose 層照舊）；
   - **skip**：判斷該批次不值得 review（一次性腳本、實驗碼）。
2. **skip 決策權轉移給模型**（user 拍板 2026-08-02，本 session 逐字：
   「人也不需要決定 skip-review 時機了，必須全部交由 AI 判斷」）：
   /kit-skip-review 改為模型可自行調用，flag 寫
   `skipped-by=model reason=<一句> scope=<N行/M檔>`；gate 收下、推進
   baseline、**留審計痕跡**（flag 內容 + toollog）。架構轉向：原設計把
   skip 做得難（防偽 + user 明說），新設計把 skip 做得**誠實且可審計**
   ——正門開著，走正門留名留理由；威脅從「會不會偷跳」變成「理由是否
   屬實」，由既有的月度抽查覆蓋。與 Anthropic 圍堵立場一致（
   [How we contain Claude](https://www.anthropic.com/engineering/how-we-contain-claude)
   2026-05-25：~93% 無腦批准率；邊界夠緊即可放鬆監督）。
3. **敏感地板保留**（user 拍板 2026-08-02）：auth/payment/migration/
   protected-paths 維持 size-blind、模型不可 skip、**亦不可 defer**——
   codex 審查（2026-08-02，Blocked P1）證明「敏感可 defer + 無編輯完成輪
   的已知缺口」等於敏感變更可實質免審，故敏感批次維持現狀語意（動碼輪
   必攔，僅 review 或 user 明說 skip 能結清）。理由：噪音來源是一般批次
   而非敏感路徑；金流/權限/schema 屬不可逆類別。
4. **審計落地（fail-closed）**：model-skip / user-skip（敏感批次）/
   defer 蓋章在生效前追加至 `/tmp/claude-kit-skiplog-<session_id>.jsonl`
   （時間、kind、reason、scope、實測行數/檔數、樹 hash）。**模型發起的
   路徑（model-skip、defer 蓋章）以寫入成功為生效前提**——skiplog 追加
   失敗（磁碟滿、/tmp 不可寫）則該決策不生效、落回 block（codex R2 P1）；
   user-approved 不受限（user 權威 > 審計，log 盡力而為）。
   **地板的強度定位（明文降格，codex R1-P1d 的替代路線）**：本 harness
   威脅模型內，持 Bash 的模型可改寫任何 /tmp 狀態檔——包括既有的
   baseline 檔（改寫 line2 即可認證任意樹，是比偽造 user-approved 或
   defer stamp 更直接的既有超集攻擊）。因此敏感地板與 skip 審計的強度
   =「誠實路徑最省力 + 造假必留可交叉比對的痕跡」（skiplog 與 flag/
   stamp 內容不一致、toollog 無對應調用即實錘），**不是密碼學保證**。
   DEFENSES 誠實條款同步此定位，月度抽查指引加 skiplog 交叉比對。
5. **順手修復兩個 pre-existing gate 洞**（codex 本輪發現，非 v4.9 引入）：
   (a) 改動清單 `head -50` 截斷發生在業務檔過濾**之前**，50 個排序靠前的
   非業務檔可把敏感業務檔擠出視野並推進 baseline——過濾先於截斷，截斷
   只留給顯示層；(b) `migrations/*.sql` 不在業務副檔名清單內，宣稱的
   migration 地板實際攔不到 SQL——敏感掃描改在副檔名過濾前對全改動集
   獨立執行。
4. Hook 變更走 hooks-smoke RED-GREEN：以本次連攔場景（>150 行批次 +
   連續動碼輪）重放為 RED，新行為（首攔後 defer → 靜默 → +150 再攔）
   為 GREEN；敏感地板與 marker 證據化的既有測項不得鬆動。

## 6. 明確不做（防 scope creep）

- **驗證閉環全套歸 v4.10**：verification-signals 新 S6（觀察層閉環：
  資訊不夠→補結構化 log→重跑→再定位；AI 擁有執行環境）、PROJECT.toml
  `[env]` preflight（runtime/權限/服務宣告 + check 指令）、測試階梯
  （純邏輯→jsdom→真瀏覽器）、real-path integration 優先於 mock。
- **wiki/代碼強綁定**：不排程。觸發條件 = 同一專案第二次 R1.2
  （修 A 壞 B）。第一道防線是測試覆蓋 + S5 高內聚（true/false 的
  contract 優於 prose）。
- **model-conditional rule loading**：等 Phase 2 的降級數據顯示強烈
  檔位依賴再議。
